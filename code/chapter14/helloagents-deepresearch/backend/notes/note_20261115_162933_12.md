# 任务 3: 应用场景与对比

目标：明确 asyncio 的适用场景（如 I/O 密集型任务），并对比其与多线程、多进程在并发处理上的差异和优劣势。检索方向：Python asyncio 应用场景 多线程 多进程 对比 I/O 密集型

### 任务 3 总结：应用场景与对比
1. **并发模型本质与 GIL 突破**：asyncio 基于单线程事件循环和协程（协作式多任务），彻底规避了 GIL 限制；多线程受 GIL 限制无法实现 CPU 并行；多进程通过独立内存空间绕过 GIL。
2. **I/O 密集型场景的极致效能**：在 I/O 密集型任务中，asyncio 上下文切换开销极低（微秒级），相比多线程（毫秒级）能支撑更高并发（C10K+），且内存占用极低（协程 KB 级 vs 线程 MB 级）。
3. **适用边界与混合架构设计**：asyncio 不适合 CPU 密集型任务（会阻塞事件循环）。工程上常采用混合架构：主事件循环处理 I/O，通过 `run_in_executor` 将 CPU 密集型或阻塞 I/O 卸载到线程池/进程池。
4. **历史演进与生态兼容性**：从 `yield from` 到 `async/await` 语法演进。痛点在于异步“传染性”及部分同步库不兼容，需使用 `asyncio.to_thread` 或原生异步库（如 aiohttp）。
