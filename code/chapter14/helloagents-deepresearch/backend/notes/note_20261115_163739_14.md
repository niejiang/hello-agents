# 任务 1: 核心概念解析

目标：明确 asyncio 中事件循环、协程、任务及 Future 的定义与相互关系。
查询方向：Python asyncio event loop coroutine task future explanation

## 核心概念深度解析

### 1. 事件循环 (Event Loop)
- **定义**：asyncio 的核心引擎，负责调度和执行异步代码。它是一个无限循环，不断检查是否有待处理的任务（Task）或回调（Callback）。
- **原理**：基于 I/O 多路复用（如 select, epoll, kqueue），在非阻塞 I/O 操作完成时通知程序继续执行。
- **价值**：实现了单线程下的并发，避免了多线程上下文切换的开销和锁竞争问题。

### 2. 协程 (Coroutine)
- **定义**：使用 `async def` 定义的函数，调用时返回一个协程对象（coroutine object），而非直接执行。
- **特性**：可暂停（await）和恢复。是异步编程的基本单元。
- **区别**：不同于生成器（generator），协程专为异步 I/O 设计，支持 `await` 语法糖。

### 3. 任务 (Task)
- **定义**：协程的包装器，用于在事件循环中调度协程的执行。通过 `asyncio.create_task()` 创建。
- **作用**：将协程提交给事件循环，使其成为“可调度”的单位。支持取消（cancel）、查询状态等操作。
- **关系**：Task 是 Future 的子类，因此具备 Future 的所有特性。

### 4. Future
- **定义**：表示一个尚未完成的操作的最终结果。它是低级对象，通常用于桥接基于回调的代码和 async/await 代码。
- **用途**：作为底层机制，Task 继承自 Future。开发者通常直接操作 Task，但在编写底层库或与旧代码交互时会用到 Future。
- **状态**：pending, cancelled, finished (with result or exception)。

## 相互关系图谱
- **Event Loop** 驱动 **Task** 的执行。
- **Task** 封装 **Coroutine**，并继承 **Future** 的状态管理能力。
- **Coroutine** 通过 `await` 挂起，等待 **Future**（或另一个 Task）的结果。
- **Future** 是连接回调风格与协程风格的桥梁。

## 工程实践建议
- 优先使用 `async/await` 语法，避免直接使用 `yield from` 或底层 Future API。
- 使用 `asyncio.create_task()` 而不是 `ensure_future()`（后者更偏向底层）。
- 注意异常处理：未捕获的异常会在 Task 完成时记录，但不会中断事件循环，需显式处理。
