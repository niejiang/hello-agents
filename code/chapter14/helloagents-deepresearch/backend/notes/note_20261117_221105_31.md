# 任务 3: 流程与最佳实践

任务目标：调研高效召开 spec 会议的标准流程。检索方向：how to run a spec review meeting best practices agenda。

关键发现总结：
1. **核心范式转变：从“朗读式”到“静默阅读+决策导向”**
   - 传统误区：会议中逐字朗读文档，导致低效和信息不对称。
   - 最佳实践：采用“静默阅读开场”（Silent-read open），参会者在会议开始前或最初几分钟内独立阅读 Spec，会议时间仅用于讨论歧义、风险和决策。
   - 价值：将认知负荷前置，确保会议聚焦于高阶逻辑和边界情况，而非基础信息同步。

2. **结构化议程：固定四块式议程（Fixed Four-Block Agenda）**
   - 结构建议：
     1. 背景与目标对齐（5-10% 时间）
     2. 静默阅读/快速回顾（15-20% 时间）
     3. 角色化深度评审（50-60% 时间）：不同角色关注不同层面（如工程关注可行性，产品关注业务逻辑，设计关注体验）。
     4. 决策与行动项确认（10-15% 时间）：明确谁在何时前完成什么。
   - 价值：通过时间盒（Time-boxing）强制收敛，避免发散性讨论。

3. **角色化评审机制：各司其职而非全员泛读**
   - 原则：每个角色应提出与其职责特定的问题，而非所有人审查同一表面。
   - 角色分工示例：
     - 产品经理（PM）：验证需求完整性、业务价值、验收标准。
     - 工程师（Eng）：评估技术可行性、系统影响、潜在风险、估算准确性。
     - 设计师（Design）：检查交互一致性、视觉规范、边缘状态处理。
     - QA：识别测试盲区、可测试性。
   - 价值：最大化专业视角的深度，减少重复劳动，提升评审覆盖率。

4. **产出物刚性要求：会前预写与会后即时记录**
   - 会前：Spec 文档必须提前分发，且包含清晰的变更标记。
   - 会中/会后：必须记录“决策日志”（Decision Log）和“行动项”（Action Items），明确 Owner 和 Deadline。
   - 关键指标：会议结束前，所有人必须对“下一步做什么”达成共识，否则视为会议失败。
   - 价值：确保评审结果可追溯、可执行，避免“会而不议，议而不决”。
