# 任务 2: 并发机制对比

目标：辨析 asyncio 异步并发与传统多线程/多进程并发的区别、优势及适用场景。
查询方向：Python asyncio vs threading vs multiprocessing performance comparison

## 关键发现补充

### 1. 核心机制差异：协作式 vs 抢占式
- **Asyncio (协作式)**：基于单线程事件循环（Event Loop）。任务通过 `await` 显式让出控制权，无上下文切换开销，但需代码显式支持异步。
- **Threading (抢占式)**：基于操作系统线程。由 OS 调度器决定切换时机，存在 GIL（全局解释器锁）限制，同一时刻只能有一个线程执行 Python 字节码。
- **Multiprocessing (并行式)**：基于独立进程。每个进程有独立的 Python 解释器和内存空间，完全绕过 GIL，实现真正的多核并行。

### 2. 性能瓶颈与适用场景辨析
- **I/O 密集型**：Asyncio 优势最大。在处理成千上万个网络连接（如 WebSocket、HTTP 请求）时，内存占用远低于线程（每个线程约 8MB 栈空间，而协程仅几 KB），且无锁竞争。
- **CPU 密集型**：Multiprocessing 是唯一选择。Asyncio 和 Threading 均受限于单核 CPU 能力，无法加速计算任务。
- **混合场景**：Threading 适合简单的阻塞 I/O 调用（如同步数据库驱动），无需重构代码为异步，但并发度受限。

### 3. 工程实践中的复杂度权衡
- **Asyncio**：学习曲线陡峭，需处理“异步污染”（async def 传播），调试困难（堆栈追踪不直观），但生态日益成熟（aiohttp, asyncpg）。
- **Threading**：易引发竞态条件（Race Condition），需熟练使用 Lock/RLock，死锁风险高。
- **Multiprocessing**：进程间通信（IPC）成本高（序列化/反序列化开销），启动慢，资源消耗大。

### 4. 历史演变与趋势
- Python 3.4 引入 asyncio，3.5 引入 async/await 语法糖，标志着 Python 从“伪并发”向“高并发异步”转型。
- 随着 CPython 3.13+ 对自由线程（Free-threading）的探索，未来 Threading 可能突破 GIL 限制，但短期内 Asyncio 仍是高并发 I/O 的首选。
