# 任务 4: 基础代码实践

目标：获取使用 async/await 语法编写基本异步程序的最小可行示例及常见陷阱。
查询方向：Python asyncio basic example async await tutorial common mistakes

## 关键发现总结

### 1. 核心机制：单线程并发与事件循环调度
- **含义**：`asyncio` 并非多线程或多进程，而是基于**单线程**的协作式多任务处理。其核心是**事件循环（Event Loop）**，它负责调度和执行可等待对象（Awaitables，主要是协程 Coroutines）。
- **价值**：避免了线程切换的开销和锁竞争问题，特别适合 I/O 密集型任务（如网络请求、文件读写）。通过 `async` 定义协程，`await` 挂起当前任务并让出控制权，使其他任务得以运行。

### 2. 最小可行示例 (MVP) 结构
- **代码范式**：
  ```python
  import asyncio

  async def main():
      print("开始")
      await asyncio.sleep(1)  # 模拟 I/O 操作，非阻塞等待
      print("结束")

  asyncio.run(main())  # Python 3.7+ 推荐入口
  ```
- **关键点**：必须使用 `asyncio.run()` 作为顶层入口来启动事件循环；直接在普通函数中调用 `await` 会报错。

### 3. 常见陷阱与误区
- **阻塞事件循环**：在 `async` 函数中使用同步阻塞调用（如 `time.sleep()` 而非 `asyncio.sleep()`），会导致整个事件循环停滞，失去并发优势。
- **忘记 await**：调用协程函数但不加 `await`，只会返回一个 coroutine 对象而不会执行，导致“静默失败”。
- **混合同步与异步代码**：在异步上下文中直接调用耗时的同步库，需使用 `loop.run_in_executor()` 将其卸载到线程池或进程池中执行。

### 4. 历史演变与工程实践
- **演变**：从 Python 3.4 引入 `asyncio`，到 3.5 引入 `async/await` 语法糖，再到 3.7 简化为 `asyncio.run()`，API 逐渐趋向简洁和易用。
- **工程建议**：优先使用高级 API（如 `asyncio.gather`, `asyncio.create_task`）管理并发任务；避免手动管理底层 Future 对象，除非有特定性能优化需求。
