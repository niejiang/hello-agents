# 任务 1: 核心概念与机制

## 任务概览
- **任务主题**: Python asyncio 的基本概念和用途
- **任务名称**: 核心概念与机制
- **任务目标**: 探究事件循环、协程、任务和 Future 的底层工作原理及相互调度关系。

## 核心发现
1. **事件循环 (Event Loop)**: asyncio 的心脏，基于 OS I/O 多路复用 (epoll/kqueue)，负责监听和分发 I/O 事件，调度协程执行。底层采用 Run-to-completion 模型，避免竞态条件。
2. **协程与 Task/Future**: 协程是状态机，Task 封装协程并继承 Future，负责在事件循环中调度并管理生命周期。3.11 的 TaskGroup 进一步优化了结构化并发。
3. **单线程并发模型**: 协作式多任务，规避 GIL 和锁开销，适合 I/O 密集型。但需警惕阻塞操作，工程上需结合 run_in_executor 处理 CPU 密集型任务。
4. **历史与生态对比**: 从 yield from 到 async/await 再到零成本抽象。相比 Node.js 面临 async 病毒问题，相比 Go 的抢占式调度，Python 采用协作式，需显式管理挂起点。
